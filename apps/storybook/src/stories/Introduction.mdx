## How it fits together

The **tokens** (`@kalads/tokens`) hold every colour, size, font and shadow, in three layers:

- **Core tokens:** the primitive values, such as `color.primary.500` or `color.danger.200`.
- **Semantic tokens:** tokens named for their purpose, such as `semantic.text.link-hover` or
  `semantic.interactive.accent`. Use these in your own code; they also switch with the theme.
- **Component tokens:** every component is fully tokenised (`component.button.primary.bg-hover`), so the
  same design can be delivered to different environments: tech stacks and devices.

On top of the tokens:

- **Icons** (`@kalads/icons`): `<kds-icon-*>` elements for the web, and icon components for React and
  React Native.
- **Components:** `@kalads/web-components` (`<kds-*>` elements), `@kalads/react-components` and
  `@kalads/react-native-components`. They are built from the component tokens: change a token and every
  library follows.

## Using these docs

- **Designers:** start with Foundations and the Usage section on each component page.
- **Developers:** start with Getting Started. Each component page has a props table and its code in all
  three libraries.
- **Coding agents:** install the agent skill that ships with the component packages
  (`pnpm exec kalads-skills`, see **Guidelines/Agent Skills**). It has these docs' rules, components and
  tokens in the agent's own platform terms.
